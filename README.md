# Table Club

33종 보드·카드·퍼즐·아케이드 게임. 내보낸 `Table-Club.html`은 설치 없이 브라우저에서 열 수 있습니다. 개발·빌드는 Node.js 22 이상에서 아래 명령을 사용합니다. 빌드 도구 esbuild는 개발용이며 실행 HTML에는 필요하지 않습니다.

```sh
npm ci
npm start
npm test
npm run export
```

서버 기본 포트는 3000(`PORT`로 변경 가능), 내보내기 결과는 `dist/Table-Club.html`입니다. 이미지와 효과음을 파일에 내장하므로 실행 시 인터넷 연결이 필요하지 않습니다. `npm run package`는 실행용 HTML과 개발 원본을 ZIP으로 묶습니다.

## 현재 모드

- 컴퓨터 / 로컬 2인: 리버시, 헥사 세균전, 오목, 야찌, 닷츠 앤 박스, 나인 멘스 모리스, 체커, 체스, 뱀과 사다리, 알까기, 고누, 장기, 윷놀이, 만칼라, 커넥트 포, 토끼와 사냥개, 헥스, 루미큐브, 도미노, 배틀십, 카롬, 쿼리도, 펜타고.
- 컴퓨터 상대: 블랙잭은 딜러 대전, 섯다·세븐 포커는 나 + 컴퓨터 4명의 5인전입니다.
- **1인 전용**: 스파이더, 스네이크, 팩맨 방식의 미로 먹기, 2048, 테트리스, 블록깨기. 히트 앤드 블로도 컴퓨터가 만든 암호를 혼자 푸는 게임입니다. 이 일곱 게임에는 대전 버튼이나 상대 보드가 없습니다.

로비에는 게임 이름 검색·검색 초기화·카테고리·즐겨찾기·최근 플레이 4개가 있으며 난이도와 소요 시간은 표시하지 않습니다. 게임 진행은 새로고침하면 초기화되며 효과음 설정·즐겨찾기·최근 플레이·최고 점수는 브라우저에 저장됩니다.

## 카드게임

- 섯다: 두 패 중 공개할 패를 선택합니다. 비공개 패는 내 화면에서 살짝 흐리게 표시하고 상대에게는 뒷면으로 보여 줍니다. 광땡, 땡, 알리~세륙, 끗과 구사·멍텅구리 구사·땡잡이·암행어사를 지원합니다.
- 세븐 포커: 4장 중 1장을 버리고 1장을 공개한 뒤 총 7장 중 5장을 사용합니다. 같은 숫자끼리 조합하는 족보와 킥커를 판정합니다.
- 두 게임 모두 아래 **족보 보기**, **현재 최고 족보**, 마지막 베팅 후 **사용할 족보 선택**을 제공합니다. 포커는 가능한 21개 5장 조합, 섯다는 해당 패로 만들 수 있는 일반·특수 족보 중 고릅니다.
- 구사는 알리 이하, 멍구사는 땡 이하일 때 기존 판돈을 유지해 재경기합니다(최대 3회). 땡잡이는 1~9땡, 암행어사는 13/18광땡에만 승리합니다. 조건이 성립하지 않는 특수 선택은 패배합니다.
- 고정 리밋, 체크·콜·레이즈·폴드, 부족한 칩의 올인과 사이드 팟을 처리합니다. 상대가 모두 폴드하면 족보 선택 없이 승리합니다. 실제 돈은 사용하지 않습니다.
- 블랙잭은 칩 이미지를 눌러 10/20/50 베팅을 선택하며, A는 유리한 값으로 자동 계산합니다. 야찌는 현재 주사위의 최고 점수와 전체 점수 안내를 제공합니다.

## 보드·아케이드

- 스파이더: 너비 1042px의 10열과 높이 740px의 고정 스크롤 보드, 88×124px 카드. 같은 무늬의 내림차순 카드 묶음을 드래그해서 쌓습니다. 클릭 이동과 되돌리기도 지원합니다.
- 알까기: 1~20알과 바둑알/장기말 선택 → 자기 진영에서 돌을 드래그해 배치 → 배치 완료 → 당겼다가 놓아 발사. 로컬 2인은 두 사람 모두 배치합니다. 마찰을 강화했습니다.
- 팩맨 방식의 미로 게임: 유령에게 잡히면 즉시 종료합니다. 큰 점의 효과 중에는 유령을 먹을 수 있습니다.
- 2048: 타일 이동·합치기·등장 모션을 지원하며 시스템의 모션 줄이기 설정을 따릅니다. 2048 달성 후에도 계속 플레이할 수 있습니다.
- 블록깨기: 클래식·피라미드·터널·체커·요새 5개 맵을 선택합니다. 맵 변경은 새 게임으로 시작합니다.
- 뱀과 사다리: 내장 SVG 보드 그림, 이동하는 말, 정확히 100 도착 규칙.
- 테트리스: 방향키, 스페이스 즉시 놓기, C 보관. 스네이크·미로·블록깨기도 키보드와 화면 조작을 지원합니다.

화면 이동 시 예약된 컴퓨터 차례·타이머·프레임·드래그를 정리하며, 모션 중 중복 입력을 막습니다. 새 아케이드 게임은 일시정지 상태에서 보드를 계속 다시 그리지 않습니다. 효과음은 인터넷에서 찾은 Kenney의 CC0 UI/Casino Audio를 Web Audio API로 재생하고 음소거하면 재생 중인 소리도 중단합니다.

## 3D·오디오·물리 업데이트

- 새 게임은 확인창 없이 동작합니다. 로컬/컴퓨터 모드, 알 개수·장기말, 블록깨기 맵, 스파이더 무늬 등 선택한 설정을 유지하며 진행과 예약된 차례·모션을 초기화합니다. 진행 중인 섯다·포커에도 새 게임 버튼이 표시됩니다.
- 야찌와 뱀과 사다리는 여섯 면의 CSS 3D 주사위를 사용합니다. 야찌의 원통형 컵에서 주사위가 쏟아져 회전하며 착지하고, 보관한 주사위는 굴리지 않습니다. 시각적인 회전과 실제 숫자 결과는 같은 상태를 사용합니다.
- 다운로드한 실제 주사위 흔들기·던지기, 카드 슬라이드, 칩 충돌·쌓기와 UI 효과음을 각 게임의 행동에 연결했습니다. 사용자 조작 후 재생하고 음소거 시 예약된 소리도 중단합니다.
- 닷츠 앤 박스는 종이와 색연필 질감의 파랑/빨강으로 표현합니다.
- 보유 칩과 판돈은 100/50/20/10/5/1의 액수별 실제 개수로 쌓아 표시합니다. 큰 더미는 12개까지 시각적으로 쌓고 총 개수 라벨을 함께 표시합니다. 베팅액을 분해한 칩이 보유 영역에서 중앙으로 이동합니다.
- 족보 창은 높은 순서의 두 줄로 나열합니다. 작은 화면에서는 각 줄을 가로로 스크롤할 수 있습니다.
- 포커에는 다운로드한 52장 카드 이미지를 크게 표시합니다. 기존 화투 그림도 유지합니다.
- 알까기 컴퓨터는 배치를 자동으로 선택합니다. 보드 바깥에 여백을 두어 가장자리에 걸친 말도 잘리지 않으며, 1~20알을 선택할 수 있습니다. 장기말 모드의 크기·질량·발사 계수와 충돌량이 다르고, 무거운 말은 느리지만 충돌 운동량이 큽니다.
- 팩맨 방식 미로는 네 유령의 최단 경로 추격·앞길 예측·측면 접근을 사용합니다. 게임판과 썸네일은 자체 제작 네온 사이버펑크 픽셀 그래픽이며 타일 사이를 보간해 부드럽게 움직입니다. 한 번 잡히면 게임 오버 규칙을 유지합니다.
- 블록깨기 아이템 8종: 패들 확대(↔), 슬로우(S), 멀티볼(●), 목숨(♥), 접착(G), 레이저(L), 관통(F), 방어막(◆). 접착된 공은 게임판 클릭 또는 공 발사 버튼으로 놓을 수 있습니다. 효과는 시간에 따라 종료됩니다.

## 디자인·사용성 정비

- 종이색 배경과 녹색 포인트, 공통 버튼·글자 대비·게임 상태 표시를 정리했습니다. 320px부터 데스크톱까지 19개 게임의 화면 넘침을 점검했습니다.
- 목록에서 게임으로 들어가면 맨 위에서 시작하며 돌아오면 목록 위치를 복원합니다. 최근 플레이는 저장된 진행이 아니라 새 판 시작 바로가기입니다.
- 실시간 1인 게임은 시작·일시정지·종료 안내를 게임판 위에 표시합니다. 창 또는 탭을 벗어나면 자동 일시정지합니다. P/Escape로 일시정지할 수 있습니다.
- 팩맨의 불필요한 120초 중단 조건을 제거하고, 블록깨기 확대 패들의 경계와 장기말의 질량별 충돌을 보정했습니다.
- 회귀 검사: 규칙 테스트 61개, 19개 게임 × 4가지 화면 너비, 검색·최근 플레이·화면 이동·일시정지·족보 창·단일 HTML 재시작 검증.

## 그래픽 재질 업데이트

19개 게임의 보드·말·테이블·캔버스 재질을 정리했습니다. 원목 나뭇결, 유광 말, 펠트 테이블, 입체 블록과 타일, 스네이크 눈과 먹이, 네온 벽의 깊이감을 사용합니다. `src/graphics.js`는 캔버스용 공통 재질을 제공하며 2048의 정지 화면과 이동 애니메이션이 같은 그래픽을 사용합니다. CSS·SVG·고해상도 캔버스로 표현하므로 추가 이미지 다운로드가 필요하지 않습니다.

## 야찌 WebGL 3D

야찌는 Three.js 0.160.1로 통·주사위·트레이를 같은 3D 공간에서 렌더링합니다. 통 기울이기, 순차 배출, 회전·튕김·정착을 시간 기반 애니메이션으로 표현합니다. 물리 엔진 시뮬레이션은 아니며, 최종 윗면은 게임에서 정한 주사위 결과와 일치하도록 회전을 맞춥니다. 보관된 주사위는 움직이지 않습니다. 통·주사위를 직접 누르거나 아래 버튼으로 조작할 수 있습니다. WebGL을 사용할 수 없는 환경에서는 기존 주사위 표시로 게임을 계속합니다.

Three.js와 MIT 라이선스는 `src/vendor/`에 포함되며 단일 HTML에도 엔진을 내장합니다. 런타임 CDN 연결은 필요하지 않습니다. 세븐 포커 썸네일은 투명 PNG에 개별 카드 바탕을 적용한 7장 부채꼴입니다.

육각 타일의 두께·진영 색조, 주황/청록 세균의 표정·광택, 선택 강조를 개선했습니다. 초록 `+`는 한 칸 복제, 파란 `↗`는 두 칸 점프이며 범례와 접근성 설명을 제공합니다. 썸네일·플레이어 패널·이동 중 세균에 같은 그래픽을 사용합니다. 320px에서는 플레이어 패널을 세로로 배치해 가로 넘침을 방지합니다.

## 실행 ZIP / 최신 수정

`npm run package`는 독립 실행 HTML과 소스를 함께 압축합니다. 배포 ZIP의 최상위 `Table-Club/index.html`은 더블클릭으로 실행하는 파일이고 `source/index.html`은 서버에서 사용하는 개발용 파일입니다. 압축을 먼저 풀고 최상위 파일을 여세요. `source` 폴더에서 개발할 때는 `npm start`를 사용합니다.

- 헥사 이동용 복제 요소가 일반 세균의 상대 위치 스타일에 덮이던 문제를 고쳤습니다. 브라우저에서 복제·점프 중의 실제 좌표 변화를 확인했습니다.
- 야찌 주사위 버튼 안에 숫자와 선택/보관 표시를 세로 정렬했습니다. 320/390/1280px에서 글자가 버튼 안에 있는지 확인했습니다.
- 체스의 ‘말 이동 · 특수 규칙’ 버튼은 6종 말 이동 그림과 캐슬링·앙파상·승격·체크/무승부 규칙을 표시합니다. 열려 있는 동안 AI는 다음 수를 두지 않습니다.
- 세 장 섯다: 모드를 선택해 세 장을 받으며 한 장을 공개합니다. 마지막에 세 가지 두 장 조합과 가능한 특수 족보 중 하나를 선택합니다. AI는 가장 높은 일반 족보를 사용합니다. 구사 재경기에서도 세 장 모드를 유지합니다. 모드 변경은 판 시작 전/종료 후 가능하며 칩과 게임을 초기화합니다.
- 규칙 테스트 68개 통과. 압축 해제한 내장 HTML을 서버 없이 로드해 위 기능과 20개 게임 목록을 검사했습니다. 클라우드 브라우저 정책으로 file:// 직접 탐색은 차단되어, 로컬 파일 더블클릭 자체는 이 환경에서 검증할 수 없습니다.

- 닷츠 앤 박스는 3×3부터 6×6 상자 크기를 선택할 수 있습니다. 변경 시 새 게임입니다.

## 알까기 물리·카드판 배치

- 경첩 두 개는 화면에 그린 직사각형과 동일한 고정 충돌체입니다. 원형 말과 경첩의 최근접점으로 충돌을 판정하고 겹침을 해소합니다.
- 속도에 따른 세부 시간 단계로 빠른 말의 관통을 방지하고, 질량별 충격량·비탄성 반발·접선 마찰·회전·판 마찰을 적용합니다. 돌 간 반발계수 0.84, 경첩 0.65인 2D 원형 강체 근사이며 실제 실측 물성 시뮬레이터는 아닙니다.
- 바둑알 초기/자동/드래그 배치는 45 단위 격자 교차점에 고정됩니다. 장기말은 기존 장기 기본 배치를 유지합니다.
- 섯다 화투를 확대했습니다. 카드판은 좌석·중앙 판돈·하단 조작 영역에 별도 레이아웃 칸을 사용합니다. 모바일에서는 중앙 판돈이 독립된 행을 사용해 큰 카드와 겹치지 않습니다.
- 족보는 높은 순서 두 줄 요약 + 조건/예시/동점 비교의 상세 목록입니다. 특수 섯다 족보는 일반 순위와 구분하고 실패·재경기 조건을 설명합니다.
- 규칙 테스트 71개와 1280/768/390/320px 카드판 겹침·버튼·족보 검증 통과.

## 반응형 게임판·팩맨 개선

- 섯다·포커의 베팅 조작 영역은 내 카드 자리 오른쪽에 유지됩니다. 작은 화면에서도 오른쪽에 두되 카드 영역은 가로 스크롤을 허용합니다.
- 알까기와 주요 게임판 크기는 화면 너비 및 높이에 따라 조정되며, 큰 화면에서는 기존보다 넓게 표시됩니다. 테트리스는 배경과 빈 칸의 격자를 제거했습니다.
- 팩맨 시작 위치는 왼쪽 아래 (1,13), 초기 보호 20틱입니다. 이동 간격은 220ms이며 유령의 5틱마다 쉬는 조건을 제거했습니다. 렌더링 보간도 같은 220ms를 사용합니다.
- 경로 탐색 결과는 목적지별 최대 64개로 제한해 재사용합니다. 팩맨 이전 프레임의 중복 깊은 복사를 제거하고, 카드 족보 후보는 손패가 바뀔 때만 다시 계산합니다.
- 규칙 테스트 72개 및 8개 게임 유형 × 1440/768/390/320px 레이아웃 검증 통과. 모든 실제 기기에서 검사했다는 의미는 아닙니다.

## 장기·윷놀이 / 팩맨 조정

- 장기: 9×10 교차점, 시작 전 마·상 4종 배치 선택, 궁성 대각선, 마·상 길막힘, 포의 넘기·포 잡기 제한, 장군·외통, 빅장 수락/해소, 한 수 쉬기, 반복/연속 쉬기 무승부. 컴퓨터 및 로컬 2인, 합법 이동 표시, 되돌리기와 규칙 안내를 제공합니다. AI는 잡기와 다음 수의 위험을 평가합니다.
- 윷놀이: 두 팀 네 말, 도·개·걸·윷·모, 업기·잡기·추가 던지기, 결과 선택, 모서리·중앙의 지름길 선택, 네 말 완주. 표시한 윷 하나만 평평한 면이 나오면 빽도입니다. 던질 기회를 모두 쓴 후 이동하며 출발점에서 한 칸 더 나가야 완주합니다. 컴퓨터·로컬 2인 및 되돌리기를 지원합니다.
- 테트리스는 내부 격자 없이 실제 10×20 적재 영역의 외곽선을 표시합니다.
- 팩맨은 이동 간격 280ms. 유령 네 마리는 각각 다른 순찰 경로를 가지며 거리 4칸 이내에서는 7~10틱 추격 후 재추격 대기 시간 동안 순찰로 복귀합니다.
- 규칙 테스트 78개 통과. 새 두 게임의 오프라인 HTML·이동·던지기·되돌리기·재시작·3가지 화면 너비를 확인했습니다. 장기 AI 12수, 윷놀이 AI 한 판 완주도 검증했습니다.


## 장기·윷놀이 실물 표현과 규칙 개선

- 장기말은 팔각형 목제 표현과 대·중·소 크기 구분(궁 / 차·포·마·상 / 사·병·졸)을 사용합니다. [PyChess 장기 가이드](https://github.com/pychess/pychess-variants/blob/master/static/docs/janggi.md)와 해당 저장소의 전통 장기말 도안을 참고해 직접 그렸습니다. 상대 크기는 1 : 0.82 : 0.60으로, 화면에 맞춰 함께 확대·축소합니다. 특정 제조사 실측치나 모니터에서의 실제 mm 크기를 뜻하지 않습니다.
- 한이 먼저, 초가 나중에 각자의 시선 기준 네 가지 마·상 배치를 선택합니다. 컴퓨터 한은 자동 선택합니다. 새 게임을 누르면 배치 단계로 돌아갑니다.
- 7종 말 이동 그림, 마·상 길목, 포의 예외, 궁성, 장군·외통·빅장 설명을 구분했습니다. 선택한 말의 설명과 목적지, 마지막 출발/도착 자리, 장군 표시 및 이동 애니메이션을 제공합니다. 장군과 빅장이 동시에 생겨도 빅장 무승부 수락이 가능합니다. 점수 판정 대신 명시된 친선 무승부 규칙을 사용합니다.
- 윷 네 개가 던지기 버튼입니다. 각 팀의 남은 말 수·대기 말·완주한 말을 판 바깥의 전용 자리에 표시합니다. 목적지를 누르면 말이 경로를 따라 이동합니다.
- 빽도는 들어온 경로를 한 칸 되짚고, 업힌 말도 함께 움직입니다. 첫째 자리에서 빽도면 출발·도착 모서리로 돌아가며 이후 앞으로 이동해야 완주합니다. 판에 움직일 말이 없고 빽도만 남으면 결과를 버리고 차례를 넘깁니다. 다른 결과가 있으면 먼저 사용해 출발한 뒤 빽도를 쓸 수 있습니다.
- 윷·모는 던질 때 추가 기회를 받으므로 그 결과로 잡았을 때 추가 기회를 중복하지 않습니다. 도·개·걸·빽도로 잡으면 한 번 더 던집니다. 이 지역별 변형 규칙은 게임 내 안내에 명시했습니다.
- 검증: 규칙 테스트 88개, 1440/768/390/320px 오프라인 HTML 조작, 장기 배치·이동·되돌리기·규칙, 윷 직접 던지기·빽도·완주 자리, 애니메이션 중 재시작/라운지 복귀를 확인했습니다. 고정 난수 8개의 윷놀이 AI 경기 완주도 확인했습니다. 브라우저 검증은 독립 HTML 내용을 로드하는 방식이며 file:// 더블클릭 자체를 검증한 것은 아닙니다.

## 카드 공개 조작·안내·AI 개선

- 세븐 포커의 7번째 패와 세 장 섯다의 3번째 패는 처음에 뒤집어 둡니다. 패를 아래로 끌어 일정 거리 이상 밀면 공개됩니다. 짧은 드래그·터치 취소는 다시 덮고, 키보드 Enter·Space·↓도 지원합니다. 확인 전에는 족보와 베팅/공개패 선택을 잠시 보류합니다. 마지막 패 공개는 상대에게 공개하는 것이 아니라 본인만 확인하는 동작입니다.
- 모바일에서 뒤집힌 마지막 패가 보이도록 손패 영역을 자동으로 가로 이동합니다. 버릴 패·공개할 패를 고를 때는 카드 간격을 벌려 클릭하기 쉽게 표시합니다. 다음 판·구사 재경기에는 다시 마지막 패를 덮습니다.
- 윷말은 대기·판 위·완주 자리 모두 청록과 빨강의 몸체 색으로 팀을 구분합니다.
- 오목은 33 허용 / 33 불가(흑만 적용)를 선택합니다. 열린 3은 한 수를 더 놓아 양끝이 빈 연속 4로 만들 수 있는 형태이며 끊어진 3도 포함합니다. 44·장목 제한은 없으며, 오목 완성이 우선입니다. 모드를 바꾸면 새 게임이며 재시작 시 선택을 유지합니다.
- 야찌 클릭음이 곧바로 이어지는 굴림 소리를 막던 문제를 해결했습니다. 효과음 제한을 종류별로 나누고 굴림·착지 음원을 함께 준비한 뒤 동일한 기준 시각으로 재생합니다.
- 22개 게임의 안내를 목표 / 번호가 있는 조작 순서 / 펼쳐 보는 추가 규칙으로 통일했습니다. 섯다 모드·오목 규칙·고누 맵에 따라 안내도 바뀝니다. 두 장·세 장 섯다 모두 세 번의 베팅 후 족보를 선택합니다.
- 장기 이동 가능 위치는 ON/OFF로 전환하며 브라우저 저장소가 허용되면 설정을 기억합니다. OFF에서도 합법 수 검사는 유지합니다. AI는 최대 4수의 반복 심화 알파베타 탐색, 잡기·재반격 탐색, 말 가치와 위치 평가, 무승부·빅장 선택을 사용합니다. 한 수당 약 360ms / 22,000노드 제한으로 기기 성능에 따라 실제 깊이는 달라집니다.
- 검증: 규칙·오디오 회귀 테스트 94개 통과. 22개 게임의 안내 표시, 1440/390/320px 카드 슬라이드·키보드 공개, 두 카드게임의 족보 선택·정산·다음 판, 33 금수 거부·허용, 장기 표시 OFF 상태의 합법 수 검사를 확인했습니다. 모바일 터치 이동·취소와 WebGL 주사위 통 터치에서 굴림·착지 오디오 소스가 시작되는 것도 확인했습니다.

## 윷놀이 화면·동작 전면 개편

- 짙은 녹색 목재 테두리, 밝은 천 질감, 청록·빨강 입체 말로 판과 썸네일을 새로 그렸습니다. 대기·완주 자리는 판 바깥에 유지하고 오른쪽 콘솔에 윷, 결과, 단계별 안내, 규칙·되돌리기·새 게임을 모았습니다. 모바일에서는 콘솔이 아래로 내려가고 현재 차례 안내가 화면 상단에 유지됩니다.
- 윷은 서로 다른 앞뒷면을 가진 CSS 3D 도형으로 회전·낙하·잔반동을 표현합니다. 평평한 면은 밝은 민무늬, 둥근 등면은 진한 나무색과 굵은 검정 X입니다. 빽도용 붉은 점은 평평한 면에 있습니다. 윷 네 개를 직접 누르면 약 1.65초 뒤 결과가 확정됩니다. 물리 시뮬레이션이 아닌 시각 애니메이션입니다.
- 말은 경로 미리보기와 함께 한 칸씩 약 360ms 간격으로 뛰어 이동합니다. 도착 후 잡힌 말이 대기 자리로 돌아가고, 업힌 말은 묶음 수를 갱신하며, 완주한 말은 각각의 완주 자리로 나뉘어 들어갑니다. 이 동작들이 끝나야 다음 차례를 표시합니다. 완주 목적지도 판 위에서 바로 누를 수 있습니다.
- 새 게임·대전 방식 전환·라운지 복귀는 진행 중 모션을 취소합니다. 이동 중 화면 크기를 바꾸면 도착 상태로 정리해 말이 엉뚱한 자리에 남지 않습니다. 모바일에서 던진 결과로 움직일 차례가 되면 판으로 부드럽게 스크롤합니다. OS의 동작 줄이기 설정을 따릅니다.

## 윷 앞뒷면과 결과 표시 수정

- 평평한 면에 X를 그려 결과가 반대로 보이던 오류를 수정했습니다. X는 둥근 등면으로 옮기고 평평한 면은 밝은 민무늬로 표현합니다. 기존의 평평한 면 개수를 세는 판정은 유지합니다: 1·2·3·4개는 도·개·걸·윷, 0개(모두 X 등면)는 모입니다. 빽도 표시가 있는 평평한 면 하나만 나오면 빽도입니다.
- 결과 아래에 평평한 면·둥근 면 개수를 함께 표시하고 규칙 안내에도 그림과 판정의 관계를 명시했습니다.
- 검증: 16가지 조합의 판정·표시 검사를 포함한 테스트 103개 통과. Chromium에서 도·개·걸·윷·모·빽도를 직접 던져 최종 3D 면 방향, X 표시, 결과, 모바일 레이아웃과 규칙 안내를 확인했습니다.

## 스파이더·알까기·팩맨 개편과 주사위 직접 조작

## 만칼라 추가 · 스파이더 썸네일 정비

## 코드 최적화

- esbuild로 실제 모듈 의존성을 묶고 JavaScript·CSS를 압축합니다. 별도의 모듈 목록과 import/export 문자열 치환을 제거했습니다. 원본 이미지는 재인코딩하지 않습니다.
- 썸네일·카드·화투·칩은 처음 사용할 때만 내장 데이터를 Blob URL로 변환하고 페이지가 열려 있는 동안 재사용합니다. 반복 렌더링 때 큰 데이터 URL을 다시 삽입하지 않습니다.
- 사용하지 않는 구형 스파이더·팩맨·알까기 화면 코드와 전용 스타일, 없어진 모드 선택 이벤트를 정리했습니다. 체스·체커의 합법 수, 게임 안내, 미로 점 좌표와 헥스 인접 관계를 캐시합니다.
- 스네이크·테트리스·블록깨기·팩맨·알까기는 대기·정지 중 프레임 예약을 쉬고 입력이나 컴퓨터 발사 시 재개합니다. 스네이크·테트리스는 실제 상태가 바뀔 때 캔버스를 다시 그립니다.
- 동일 Chromium 조건 측정: 실행 HTML 4,957,368 → 4,864,623바이트, 로비 DOM 마크업 1,151,197 → 82,599자(약 93% 감소). 알까기 준비 화면의 1초간 프레임 콜백은 59 → 0회입니다. 파일 크기와 DOM 크기는 서로 다른 지표입니다.
- 헥스 연결 비용은 전체 노드 선형 탐색 대신 0–1 BFS를 사용합니다. 동일한 100개 11×11 국면의 1,600회 계산에서 약 243 → 15ms(약 16.7배)였으며 결과는 동일합니다. 전체 AI 턴 속도를 뜻하지는 않습니다.
- 검증: 자동 테스트 136개 통과. 내보낸 HTML에서 27개 게임 입장, 체스·체커·모리스·닷츠 착수와 재시작, 카드 이미지·배분·되돌리기, 실제 스파이더 드래그, 아케이드 정지·재개·새 게임을 확인했습니다. 관리형 브라우저의 파일 URL 제한 때문에 더블클릭 대신 동일한 HTML 내용을 직접 로드했습니다.

## 배틀십 함선 그림

- 칸마다 분리된 블록을 이어진 함선 SVG로 교체했습니다. 항공모함의 비행갑판·우현 함교·함재기, 전함의 세 대형 포탑, 순양함의 가느다란 선체, 잠수함의 중앙 함교·꼬리날개, 구축함의 함포·굴뚝을 단순화했습니다. 배치 선택기·게임판·함대 상태·썸네일에서 같은 그림을 사용합니다.
- 온라인 공개 함선 자료와 아이오와 전함 박물관 관련 프로젝트의 그림을 시각 참고했습니다. 원본 사진·메시·텍스처를 가져오지 않고 게임용 도형을 새로 작성했습니다. 참고 링크와 적용 범위는 `assets/battleship/SOURCES.md`에 있습니다. 함선의 칸 수는 게임 규칙이며 실제 길이 비율은 아닙니다.

현재 컴퓨터 대전은 난이도 선택 없이 게임별 고정 알고리즘을 사용합니다. 배틀십은 관측한 명중/빗나감/격침과 남은 함선 길이로 후보 위치를 계산합니다. 도미노는 눈 합과 더블 가산점으로 패를 평가하고, 루미큐브는 최대 160개 후보 조합과 제한된 탐색으로 등록을 찾습니다. 체스는 기본 220ms/최대 3단계, 장기는 360ms/최대 4단계와 전술 연장 탐색을 사용합니다. 학습 모델 또는 공인 실력 등급을 적용한 엔진은 아닙니다.

## 카롬 · 쿼리도 · 펜타고

세 게임을 추가해 총 33종입니다. 진입 시 컴퓨터 대전 / 로컬 2인을 선택하며, 전용 썸네일·효과음·게임 안내·새 게임을 제공합니다. 그래픽은 자체 제작한 SVG·CSS·Canvas로, 실행 파일에 모두 포함됩니다.

- **카롬**: 매 샷마다 기준선의 빈 곳을 클릭해 스트라이커를 배치한 뒤, 별도로 뒤로 당겨 발사합니다. 터치와 위치·방향·힘 조절 버튼도 지원합니다. 충돌·마찰·쿠션·포켓을 계산하며 내 말 성공 시 추가 샷, 퀸 커버, 스트라이커 파울, 퀸 확보 전 마지막 말 반환을 적용합니다. 누적 대회 점수·시간 제한·미납 파울 벌점은 적용하지 않는 캐주얼 1판 규칙입니다. 컴퓨터는 포켓을 겨냥하는 후보 샷을 생성하고 물리 시뮬레이션으로 평가합니다.
- **쿼리도**: 9×9 판에서 반대편 끝줄에 먼저 도착합니다. 각자 벽 10개, 상대 말 뛰어넘기와 뒤가 막혔을 때의 대각 우회를 지원합니다. 벽 겹침·교차·어느 한쪽의 모든 경로 봉쇄를 막습니다. 컴퓨터는 최단 경로와 벽으로 늘어나는 거리를 비교합니다.
- **펜타고**: 6×6 판에 돌을 놓고 작은 판 하나를 90도 회전합니다. 착수 즉시 5목이면 회전 없이 승리하고, 회전 후 양쪽이 동시에 5목이면 무승부입니다. 회전 중 중복 입력을 차단하며 쿼리도와 함께 되돌리기를 제공합니다. 컴퓨터는 착수·회전 조합과 제한된 상대 응수를 탐색합니다.

검증: 추가 규칙 검사 13개를 포함해 총 166개 통과. 브라우저에서 이동·벽 설치·착수·회전·실제 스트라이커 드래그·컴퓨터 응수·되돌리기·새 게임·화면 이탈과 768/390/320px 화면을 점검했습니다. 별도로 모션 줄이기를 끈 펜타고의 회전과 회전 중 초기화를 확인했습니다. 브라우저 검증은 내보낸 HTML 내용을 로딩하는 방식이며, 이 환경에서 OS 파일 더블클릭은 검증하지 않았습니다.

## 세 게임 가시성·조작 개선

- 쿼리도: 벽을 두껍게 만들고 진한 코랄·청록색, 밝은 가장자리와 그림자로 강조했습니다. 방금 놓은 벽에는 추가 테두리가 표시되며 설치 미리보기와 범례도 함께 제공합니다.
- 카롬: 매 샷을 ‘클릭해 배치 → 당겨서 발사’로 나눴습니다. 배치 클릭은 발사하지 않으며 배치 전 조준·발사는 잠깁니다. 상대 차례와 연속 샷에도 위치를 다시 고릅니다. 위치 재선택, 키보드용 위치 슬라이더·배치 버튼을 지원하고 컴퓨터는 스스로 배치합니다. 배치 가능 여부는 물리 엔진과 화면이 같은 함수로 확인합니다.
- 펜타고: 버건디 판, 아이보리·미드나이트 돌로 변경하고 썸네일·회전 버튼·플레이어 색상 안내도 맞췄습니다.

이번 검증: 관련 규칙 검사 13개 통과. Chromium에서 벽 설치·미리보기, 펜타고 회전·새 색상, 카롬의 마우스·터치·키보드 배치와 발사, 차례 변경, 컴퓨터 발사, 새 게임 및 320/390/768px 레이아웃을 확인했습니다.
